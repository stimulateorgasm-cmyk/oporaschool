## Что нужно реализовать

### 🔴 1. Личный кабинет администратора (расширение профиля)

Сейчас профиль (`/auth/me`, `PATCH /auth/me`) умеет имя/фото/пароль. Добавить для сотрудников-администраторов:
- **номер телефона** (редактируемый, не у всех есть),
- **график работы** (текст/JSON — напр. «Пн-Пт 9:00–18:00»),
- **имя, фамилия** (раздельно, сейчас `full_name` слитно),
- **ставка** (число, ₽/час),
- **число отработанных смен** (целое, для учёта).

Требования:
- Поля видны и редактируются только для роли `administrator` (и `manager`).
- Отдельно от полей педагога (педагог = таблица `teachers`, админ = `users` + роли). НЕ путать: у админа может и не быть записи педагога.
- UI — в существующем `Profile.tsx` или `Header.tsx`.

### 🔴 2. Раздел «Клиенты» — возврат из архива в активные

- В карточке клиента / списке клиентов добавить действие «Вернуть в активные».
- Сейчас есть архив (мягкое удаление). Нужен обратный переход: архив → активный статус.
- Проверить: `clients.archived` (булев) или `status`. Если архив = `archived=true`, добавить `PATCH` без сброса истории.

### 🔴 3. Расписание в карточке клиента при создании

- При создании клиента (родитель + ребёнок) сразу дать возможность:
  - прикрепить **направление** (subject) к ребёнку,
  - установить **расписание**: календарь (дата), время, направление, преподаватель.
- То есть в процессе создания клиента — уже форма записи на занятие, без отдельного захода в календарь.
- Связать с существующим `POST /schedule/lessons` (создание занятия требует child_id, subject_id, teacher_id, room_id, starts_at, ends_at).

### 🔴 4. Группы учеников

- Новая сущность: **группа** (id, название, состав учеников).
- Объединять учеников (детей) в группы; давать группам названия.
- Назначать **групповые занятия** в календаре (занятие привязано к группе, а не к одному ребёнку).
- Требования:
  - Модель `groups` (id, name, created_at) + `group_members` (group_id, child_id) — m2m.
  - Занятие: расширить `lessons` полем `group_id` (nullable) + `child_id` остаётся nullable (занятие либо индивидуальное child, либо групповое group).
  - Учитывать в конфликтах расписания (validate_conflicts): нельзя наложить группу на того же педагога/кабинет/время.
  - `lesson_format` уже есть (individual/group) — использовать его.

### 🔴 5. Повторяющиеся занятия

- При планировании занятия — опция **повторения**:
  - «однократно» (по умолчанию),
  - «раз в неделю» (1x/нед),
  - «два раза в неделю» (2x/нед).
- Генерация серии занятий по правилу (без дублей, с проверкой конфликтов на каждое).
- Плюс: **планировать сразу несколько занятий в одном окне** для одного ученика (список дат/времён за один заход).

### 🟠 6. Редактирование запланированного занятия

- Сейчас есть только `POST /lessons/{id}/move` (перенос времени). Нужно полноценное редактирование:
  - изменить ребёнка/направление/педагога/кабинет/время/комментарий/вложение.
- Эндпоинт `PATCH /lessons/{id}` + UI (в LessonModal открыть существующее занятие на редактирование).

### 🟠 7. Вложения сделать НЕобязательными

- Сейчас `LessonModal.tsx` требует файл: `if (!file) setError('Прикрепите файл...')`.
- Сделать вложение **необязательным** и в создании занятия, и в карточке (вложения — по желанию, а не обязательное поле).

## Важные ограничения

1. **Время в UTC → локально на фронте.** Бэк отдаёт `starts_at`/`ends_at` как UTC (`...Z`). Фронт уже исправлен — парсит через `new Date(iso)`. Новые экраны обязаны делать так же (НЕ использовать `split('T')` для вывода времени).
2. **`status`/`lesson_format` — `String(20)` в БД**, читаются строкой, не enum. В бэке использовать `getattr(x, "value", x)`, а не `x.value`.
3. **Роли**: `manager` (руководитель Надежда), `administrator`, `teacher`. Платежи — не для `teacher`; зарплаты/аудит — не для `administrator`. Это уже частично сделано — не сломать.
4. **Таймзона сервера** — Europe/Moscow. Хранить/сравнивать даты с учётом этого.
